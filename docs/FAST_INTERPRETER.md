# FXI: a fast x86-64 interpreter for no-JIT play

**Goal.** Run x86-64 code on iOS with no executable memory at all (no StikDebug, no JIT), as
fast as an interpreter can go. Target: **10% of native** on integer code (Blink measures 0.8% on
an A17 Pro, build 20), stretch 20%. FXI is the CPU half of no-JIT play; the other half, running
Wine's own ARM64 code from signed code instead of the JIT pool, is a separate project
(docs/APP_STORE.md, "Wine's DLLs").

## Why Blink is slow, and what FXI does instead

| Cost in a classic interpreter | FXI |
| --- | --- |
| Decode every instruction every time it runs | **Pre-decode once** per basic block into a compact array of micro-ops (uops) with operands resolved; blocks cached by guest address |
| A central `switch`/dispatch loop (one unpredictable indirect branch for everything) | **Tail-call threading**: every handler ends with `[[clang::musttail]]` into the next uop's handler, so each handler has its own indirect branch the predictor learns, and nothing returns to a loop |
| Computing all six arithmetic flags after every ALU op | **Lazy flags** (keep the operands, compute a flag only when read) plus **decode-time flag liveness**: an op whose flags are overwritten before any read gets the no-flags handler |
| Generic operand decoding at run time | **Specialised handlers** per operation × operand size × form (reg/reg, reg/imm, reg/mem, mem/reg, mem/imm), generated by macros |
| Effective-address calculation with branches | **Branchless EA**: base and index are register slots (slot 16 is always 0), RIP-relative is resolved to an absolute address at decode |
| Separate guest memory with address translation | **Identity mapping**: guest addresses are host addresses (as FEX and ARM64EC do), so a guest load is one host load |
| Block-to-block lookups through a hash table | **Block chaining**: direct jumps, calls and conditional branches remember their successor block in the uop; returns and indirect jumps use a one-entry inline cache before the hash table |
| `cmp`/`test` followed by `jcc` as two dispatches | **Fusion** into one compare-and-branch uop |
| SSE emulated element by element | SSE/SSE2 on **NEON** (128-bit registers map one to one; float ops are single NEON instructions) |
| 80-bit x87 in software | x87 as `double` (FEX's "reduced precision" preset makes the same trade) |

8-bit and high-byte registers (AH, CH, DH, BH) are byte offsets into the register file, so
`mov ah, al` needs no special case. Uops are 32 bytes; a block ends at the first branch, call,
return or syscall.

## Phases

1. **Core (this commit).** Uop format, decoder for the integer instructions compilers emit,
   lazy flags with liveness, block cache and chaining, tail-call dispatch, a static-PIE ELF
   loader and the three syscalls the guest tests use (write, exit_group, clock_gettime).
   `engine/fxi/build.sh` builds a Linux host tool; CI (`fxi.yml`) runs `hello` and the
   benchmark kernels natively and under FXI, **fails if a checksum differs**, and reports FXI's
   speed as a percentage of native. An unimplemented instruction stops the guest and names its
   opcode bytes, which is the to-do list for the next commit.
2. **SSE/SSE2** for the float, memory and SIMD kernels (NEON on ARM64, SSE intrinsics on the
   x86 CI host).
3. **In the app**: build FXI for iOS and add it as a third engine on the Performance tab (FEX,
   Blink, FXI) on the same benchmark. Replace Blink when FXI is faster everywhere.
4. **Speed**: profile on device; superinstructions for hot pairs, register caching of the guest
   RSP/flags in handler arguments (`preserve_none` calling convention where the compiler has
   it), inline-cache tuning.
5. **Windows**: FXI as the CPU for Wine's x86-64 code (the role xtajit64.dll/FEX plays today),
   which needs the Wine-side no-JIT work first.

## Status (2026-10-07)

- Phases 1 and 3 done, phase 2 partly (the SSE2 subset compilers emit for the test programs, plus
  `pinsrd/q`, `pextrd/q`). All guest programs give native-identical results under FXI.
- CI host (x86-64 Linux, clang), FXI as a share of native: integer 10.8%, float 6.7%, memory 7.5%,
  branch 10.2%, SIMD 5.3%. Blink on an A17 Pro measured 0.5–1.5% on the same kernels.
- In the app since build 39: no-JIT runs use FXI; the Performance tab shows FEX, FXI and Blink.
- Next: device numbers, then phase 4 (profile-driven: SSE on NEON intrinsics, superinstructions
  for the hottest pairs, `preserve_none` dispatch).

## Honest expectations

A tuned interpreter on an A17 Pro should reach roughly 5–20% of native on compiled game code:
fine for 2D, older and lighter 3D games, not for modern 3D games. JIT (FEX, ~93% of native)
stays the way to play those; FXI is the way to play without StikDebug.

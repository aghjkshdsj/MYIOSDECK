No compilation, XCTest execution, live sign-in or live download was performed here. This machine has no Xcode or compiler. The following are runnable source tests and checks for the owner's Mac/iOS build.

Build an iOS17+ XCTest target using Swift5. Include every production Swift file in this directory, BSteamCodecs.c, tests/SteamValueTests.swift, tests/SteamPipelineTests.swift, tests/TestCodecFixtures.c, and (for a standalone target) tests/SteamHarness.swift. Use tests/TestBridging.h as that target's bridging header. Link Security, CoreFoundation, Foundation, SwiftUI, UIKit, CoreImage, Compression, CommonCrypto, zlib and liblzma, with liblzma's public headers available. BSteamCodecs.c includes vendor/zstd_decompress.c itself: do NOT compile the vendor .c as another source. In the real app, add BSteamCodecs.h to its existing bridging header and exclude the test harness, since the app already supplies LogStore and MadeiraConfig. No generated protobuf code or package manager dependency is required.

On a Mac run Product > Test, or `xcodebuild test -project <integration>.xcodeproj -scheme <SteamTests> -destination 'platform=iOS Simulator,name=<installed simulator>'`. Run under Address Sanitizer and Thread Sanitizer in separate test runs. Also build the real app in release configuration. No passing result is claimed in this document.

SteamValueTests covers text KeyValues quotes/literal Windows backslashes/comments/BOM/quoted braces/malformed input/depth/value/input limits; recursive binary KeyValues; protobuf fixed/varint/string/invalid lengths and overflow; app-info VDF fields/artwork/launch ordering/old Codable cache defaults; 64/32 depot selection; AES encrypted-IV/CBC roundtrip with hand-built test encryption; stored data, seed0 Adler and SHA1; hand-built raw-block Zstandard in a VSZa envelope, malformed Zstd returning an error instead of terminating; a REAL raw LZMA1 stream generated at test runtime by liblzma and wrapped as VZ; direct/enveloped hand-built manifest protobuf; path rejection/case folding; exact key spelling and layout of install records; numeric JWT expiry and opaque-token behavior; CM envelopes/Multi and resolve-once promise with multiple waiters and timeout; content-host validation.

SteamPipelineTests supplies BSteamScriptedSession (the same CM request protocol used by production) and BSteamScriptedContent (the same content transport used by production). It runs package tokens, binary package data, app tokens/info, depot keys, manifest-request code, CDN auth, manifest fetch/decrypt/parse, chunk AES/decode/integrity checks, real file writes, fsynced resume journals and atomic ACF creation, with no network. A12-file install is interrupted on a later chunk request, then resumed after appending a torn journal tail and creating a stale-manifest journal. It asserts prior chunks are reused, concurrency is at most8, progress spacing is at least0.25s, records and custom-executable manifest cache appear only after content is complete, and resume state is removed. A new build changes one file and downloads only that chunk. It also tests shared-owner ACF merging, case-insensitive executable lookup, symlink escape rejection and uninstall confinement.
